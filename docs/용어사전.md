# 용어사전

이 저장소의 문서·코드·데이터에 나오는 말을 한곳에 모았다. 처음 보는 사람이 문서를 읽다가 막히면 여기서 찾는다.

- 1장 부동산·주소 개념 → 2장 모델·검증 개념 → 3장 입력·출력 컬럼 → 4장 데이터 파일 컬럼 → 5장 모델 변수(코드 이름)
- 수치의 근거는 의사결정 문서(`docs/의사결정/`)에 있고, 여기서는 뜻만 적는다

## 1. 부동산·주소 개념

### PNU (필지 고유번호)

땅 한 필지마다 붙는 **19자리 번호**다. 주소를 글자(동 이름·지번)로 맞추면 띄어쓰기·표기 차이로 어긋나기 쉬워서, 이 프로젝트는 모든 데이터를 PNU로 연결한다.

```text
1150010300 1 0162 0008
└법정동코드┘ │ └본번┘└부번┘
 (10자리)   산 여부(1 = 일반, 2 = 산)
```

예: `1150010300101620008` = 법정동코드 `1150010300`(서울 강서구 화곡동) + 일반 땅 + 162번지 8호 → **화곡동 162-8**

만드는 코드: `src/collect_buildings.py`의 `to_pnu`

| 용어 | 뜻 |
|---|---|
| 법정동코드 (`bjd_cd`) | 법으로 정한 동마다 붙는 10자리 번호. 시도 2 + 시군구 3 + 읍면동 3 + 리 2. 예: `1150010300` 화곡동, `1162010100` 관악구 봉천동, `1168010100` 강남구 역삼동. 원본은 `data/reference/법정동코드_국토교통부_20260630.csv` |
| 시군구코드 (`sgg_cd`) | 법정동코드 앞 5자리. `11500` 강서구, `11620` 관악구, `11680` 강남구 |
| 법정동 vs 행정동 | 법정동은 땅·등기에 쓰는 동(화곡동, 봉천동). 행정동은 주민센터 단위로 나눈 동(화곡1동, 낙성대동). 실거래·공시가격·건축물대장은 모두 **법정동**을 쓴다 |
| 지번 (`jibun`) | 땅의 번지. `본번-부번`(예: 162-8). 부번이 없으면 본번만(162). 앞에 "산"이 붙으면 산 지번 |
| 필지 | 지번 하나에 해당하는 땅 한 덩어리. 빌라 한 동은 보통 필지 하나 위에 있다 |

### 집과 가격

| 용어 | 뜻 |
|---|---|
| 다세대주택 | 4층 이하, 한 동의 주거 바닥면적 합이 660㎡ 이하인 공동주택. 흔히 말하는 "빌라" |
| 연립주택 | 4층 이하, 주거 바닥면적 합이 660㎡를 넘는 공동주택. 다세대보다 조금 큰 빌라 |
| 전용면적 (`area_m2`) | 현관 안쪽, 그 집만 쓰는 면적(㎡). 계단·복도 같은 공용면적은 빠진다 |
| 호 (`ho`) | 집 번호(201호 등). 데이터마다 "3층301호", "B01", "비01"처럼 다르게 적혀 있어 통일 규칙을 따로 만들었다(`src/ho.py`) |
| 실거래가 | 실제로 사고판 가격. 국토교통부에 신고된 값 |
| 공시가격 (공동주택가격) | 정부가 매년 1월 1일 기준으로 **집(호) 하나하나**에 매기는 가격. 세금 기준이라 보통 시세보다 낮다. 이 권역 거래의 실거래/공시 비율 중앙값은 1.76(1007_15) |
| 개별공시지가 | 정부가 **땅 1㎡**에 매기는 가격. 공시가격(집)과 다르다. 이 프로젝트에서는 입지 수준을 나타내는 변수로 쓴다 |
| 지목 (`land_category`) | 땅의 용도 구분. 대(대지)·도(도로)·전(밭)·답(논)·임(임야)·잡(잡종지) 등 |
| 해제 거래 | 신고한 뒤 계약이 취소된 거래. 정제할 때 뺐다 |
| 중개거래 / 직거래 | 공인중개사를 거친 거래 / 사고파는 사람이 직접 한 거래. 직거래는 가족 간 거래처럼 시세와 다른 경우가 많다. 2021-11 이전 거래는 이 항목이 없어 "미상" |
| 건축물대장 표제부 | 건물 한 동의 기본 정보(층수·세대수·승강기·주차·사용승인일 등)를 적은 공문서. 건축HUB API로 받았다 |
| 사용승인일 | 건물을 다 짓고 써도 된다고 허가받은 날. 연식 계산과 "재건축 전 거래" 판별에 쓴다 |
| 연식 (`age`) | 거래 연도 − 건축 연도 |

## 2. 모델·검증 개념

### 시세를 어떻게 추정하나

| 용어 | 뜻 |
|---|---|
| AVM | Automated Valuation Model. 사람 대신 데이터로 시세를 자동 산정하는 모델 |
| B1 (기본 추정) | **공시가격 × 실거래/공시 비율**. 이 프로젝트의 뼈대. PPT에서는 "기본 추정" |
| 실거래/공시 비율 (`public_ratio`) | 실거래가 ÷ 공시가격. 공시가격이 시세를 얼마나 덜 따라가는지를 나타낸다. 같은 건물 → 법정동 → 구 순서로 찾는다 |
| 당기기 (shrinkage) | 같은 건물 거래가 1～2건뿐이면 그 비율만 믿기 어렵다. 그래서 동네(법정동) 비율 쪽으로 당겨 섞는다: (n × 건물 비율 + 2 × 동네 비율) ÷ (n + 2). n = 같은 건물 거래 수 |
| 시점 지수 (TimeIndex) | 구별·월별 가격 흐름. 2년 전 거래를 기준일(2026-10-06) 가격으로 옮길 때 쓴다. 매달 중앙값을 3개월 이동평균한다 |
| 기준일 | 시세를 매기는 날짜. 2026-10-06 |
| 학습 기간 | 모델이 배우는 거래의 기간. 최근 **3년**(3·5·6년을 비교해 고름, 1007_13) |
| XGBoost | 결정나무(예/아니오 질문을 이어 붙인 규칙)를 수백 개 쌓아, 앞 나무가 틀린 부분을 다음 나무가 고치는 기계학습 모델. PPT에서는 "기계학습 보정" |
| 직접 / 잔차 / 평균 | XGBoost를 쓰는 세 방식. **직접**: 건물·입지 정보로 ㎡당 가격을 바로 맞힌다. **잔차**: B1이 얼마나 빗나갔는지(실거래 ÷ B1)를 맞혀 B1을 고친다. **평균**: 두 결과의 기하평균. 최종 모델은 평균(XGB-평균) |
| 기하평균 | 두 값을 곱해 제곱근을 취한 평균. √(a × b). 가격처럼 배율로 움직이는 값에 쓴다 |
| 로그 (log) | 큰 값을 줄여 배율 차이를 덧셈 차이로 바꾸는 변환. 1억과 2억의 차이 = 5억과 10억의 차이가 된다. 가격·면적·거리 변수에 쓴다 |
| 헤도닉 변수 | 집의 특성(층·연식·승강기·역 거리 등)으로 가격을 설명하는 변수. 코드의 `HEDONIC` |
| 실행 중 조회 | 입력 지번이 미리 받아 둔 데이터에 없을 때만 공시가격·건축물대장을 그 자리에서 API로 조회하는 기능(1007_12) |

### 얼마나 맞는지 어떻게 재나

| 용어 | 뜻 |
|---|---|
| 오차율 (APE) | \|추정 − 실거래\| ÷ 실거래. 3억짜리를 3.3억으로 추정하면 10% |
| 중앙값 오차 | 오차율을 줄 세웠을 때 가운데 값. 극단적인 몇 건에 덜 흔들린다. PPT에서는 "보통 차이" |
| MAPE | 오차율의 평균. 크게 틀린 건이 있으면 중앙값보다 커진다 |
| ±20% 적중률 | 추정이 실거래가의 ±20% 안에 든 비율. "10건 중 8건" |
| 80% 구간 (`price_low`～`price_high`) | 실제 가격이 10번 중 8번은 이 안에 들도록 잡은 범위 |
| 포함률 | 실제 가격이 80% 구간 안에 실제로 든 비율. 80%에 가까우면 구간이 정직하다 |
| 신뢰도 (`confidence`) | "검증에서 비슷한 조건의 추정이 실거래가 ±20% 안에 든 비율". 0.8이면 비슷한 물건 10건 중 8건이 ±20% 안에 들었다는 뜻 |
| 오차 점수 | 추정이 얼마나 틀릴지 미리 가늠하는 점수. 같은 건물 거래 수, 동네 비율의 흩어짐, 지하층·30년 초과 등 예측 때 아는 값으로 계산한다(5장 `ERR_FEATURES`) |
| 10분위 | 오차 점수 순으로 줄 세워 10묶음으로 나눈 것. 묶음마다 실제 오차를 보고 구간 폭과 신뢰도를 정한다 |
| 단조 보정 (isotonic) | "점수가 나쁠수록 신뢰도는 같거나 낮아야 한다"는 순서를 지키면서 신뢰도를 실제 적중률에 맞추는 방법 |
| 보정표 (`calibration.json`) | 10분위 경계·구간 폭·신뢰도를 저장한 파일. `src/build_calibration.py`가 만든다 |

### 시험은 어떻게 했나

| 용어 | 뜻 |
|---|---|
| 홀드아웃 | 모델을 만들기 전에 **미리 떼어 둔** 시험용 데이터. 학습·보정에 전혀 쓰지 않는다. 이 프로젝트는 건물 632개(`holdout_pnu.csv`) |
| 건물 단위로 뗀다 | 같은 건물의 다른 호 거래가 학습에 남아 있으면 답을 엿보는 셈이라, 거래가 아니라 건물(PNU) 단위로 뗐다 |
| 상황 A / B / T | **A**: 처음 보는 건물(같은 건물 거래를 모름). **B**: 같은 건물 과거 거래가 있음. **T**: 시점 밖 — 2025-09 이전으로만 배우고 그 뒤 거래를 맞힘(새 데이터·물가 변화에 견디는지) |
| 데이터 누수 | 예측 때는 모르는 정보(정답이나 미래 거래)가 학습에 섞여 성적이 부풀려지는 것 |
| 교차검증 / GroupKFold | 학습 데이터를 몇 묶음으로 나눠 돌아가며 시험하는 방법. GroupKFold는 같은 건물이 배우는 쪽과 시험 쪽에 섞이지 않게 건물(PNU)로 묶어 나눈다 |
| 그리드서치 | 모델 설정값(나무 깊이·개수 등) 조합을 표처럼 늘어놓고 전부 시험해 가장 나은 것을 고르는 방법 |
| 부트스트랩 | 시험 결과를 무작위로 다시 뽑기를 반복해, 두 모델 차이가 우연인지 확인하는 방법 |
| 기준선 | 비교의 출발점이 되는 단순한 모델. 이 프로젝트는 B1(공시가격 × 비율만) |
| 보정 표본 | 구간·신뢰도를 맞추는 데 쓴 별도 거래. 홀드아웃과 겹치지 않는다 |

### 데이터 점검에 쓴 말

| 용어 | 뜻 |
|---|---|
| 이상치 | 다른 거래와 동떨어진 값. 무조건 지우지 않고, 낮은 쪽만 빼고 높은 쪽은 표시만 했다(1007_04) |
| 수정 Z-점수 (`outlier_z`) | 값이 무리의 가운데(중앙값)에서 얼마나 떨어졌는지를 MAD로 나눈 점수. ±3.5를 넘으면 이상치로 본다 |
| MAD | 중앙값에서 떨어진 거리들의 중앙값. 표준편차와 비슷하지만 극단값에 덜 흔들린다 |
| VIF / 공선성 | 두 변수가 사실상 같은 정보를 담는 정도. 예: 연식 = 거래연도 − 건축연도라서 셋을 함께 넣으면 안 된다 |
| 결정계수 (R²) | 한 변수가 가격 차이를 얼마나 설명하는지(0～1). log 실거래가를 log 공시가격 하나로 0.87 설명(1007_15) |
| 일괄 매매 | 여러 호를 한 번에 사고팔아 호마다 합계 금액이 적힌 거래. 12건 뺐다(1007_11) |
| 재건축 전 거래 | 지금 건물이 지어지기 전, 옛 건물 때 거래. 580건 뺐다(1007_11) |

## 5. 모델 변수 (코드 이름)

### XGBoost 입력 (`src/ml.py`)

| 코드 이름 | 뜻 |
|---|---|
| `log_public_m2` | 공시가격 ÷ 면적(㎡당 공시가격)의 로그 |
| `log_area` | 전용면적의 로그 |
| `floor`, `is_basement`, `is_top_floor` | 층, 지하 여부, 최상층 여부 |
| `rel_floor` | 상대 층 = 층 ÷ 지상층수(5층 건물의 5층 = 1.0) |
| `age` | 연식 |
| `elevator` | 승강기 유무 |
| `grnd_flr` | 지상층수 |
| `log_hhld` | 세대수의 로그 |
| `parking_per_hhld` | 세대당 주차 대수 |
| `log_station` | 가장 가까운 지하철역까지 거리(m)의 로그 |
| `log_land` | ㎡당 개별공시지가의 로그 |
| `lon`, `lat` | 필지 중심 경도·위도 |
| `gangnam`, `hwagok` | 강남구면 1, 화곡동이면 1(둘 다 0이면 관악구) |
| `b1_ratio` | B1에 쓴 실거래/공시 비율(당기기 후) |
| `area_ratio`, `area_sd` | 동네(법정동·구) 비율의 중앙값, 흩어짐 |
| `b_n`, `b_sd`, `b_gap` | 같은 건물 거래 수, 같은 건물 비율의 흩어짐, 같은 건물 비율 − 동네 비율 |

직접 방식은 `log_public_m2`～`hwagok`(`HEDONIC`)만, 잔차 방식은 여기에 `b1_ratio`～`b_gap`(`B1_FEATS`)을 더 쓴다.

### 오차 점수 입력 (`src/avm.py`의 `ERR_FEATURES`)

| 코드 이름 | 뜻 |
|---|---|
| `const` | 상수항 |
| `gangnam`, `hwagok` | 권역 |
| `log_area` | 면적의 로그 |

| `basement`, `old` | 지하층, 30년 초과 건물 |
