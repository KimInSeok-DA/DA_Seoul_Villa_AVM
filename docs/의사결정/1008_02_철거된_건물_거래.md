# 1008_02 철거된 건물의 거래를 학습에서 빼기

- 상태: 확정 (사용자 제안·결정, 2026-10-08). [1007_02](1007_02_건물정보_결측_처리.md)의 학습 거래 처리를 바꾼다
- 코드: `src/collect_closed_titles.py`(수집·정제), `src/build_trades.py` 7단계 "철거된 건물 거래 제외"
- 데이터: `data/reference/closed_titles.csv`(폐쇄말소대장 표제부, 3개 구), 원본 `data/raw/closed_titles.csv`(저장소 제외)
- 함께 고친 것: `notebooks/make_01_baseline.py`가 실행할 때마다 검증 건물을 다시 뽑던 것 → 고정 파일을 읽도록(§6)

## 1. 문제

현행 건축물대장에 건물이 없는 지번 114개의 거래 544건을 1007_02에서 학습에 남겨 두었다. 이유는 "시점 지수·비교사례에 쓸 거래를 버리지 않는다"였다. 하지만 두 가지 문제가 있었다.

- 이미 없는 건물이다. 예측할 일이 없는 건물의 거래로 모델을 배우게 된다.
- 건물 정보가 근사값이다. 층수·세대수를 마지막 공시가격의 층·호 수로 채웠고, 승강기·주차는 비어 있다. 신축 건물이 같은 지번에 섰다면 옛 건물의 값이 새 건물에 붙는다.

당시 "철거된 건물"이라는 판단도 공시가격이 끊긴 해와 주소 검색으로 짐작한 것이었다(1007_02).

## 2. 방법

1. **폐쇄말소대장 수집**: 서울 열린데이터광장 OA-22432 "서울시 폐쇄말소대장 표제부"(Open API `vBigDjrShTitle`)를 쓴다.
   - 지번으로 골라 조회하는 인자가 없어 서울 전체 383,716건을 1,000건씩 받고 3개 구 51,149건만 남겼다.
   - 구·법정동·주지번·부지번으로 PNU를 만들었다. 블록 지번 등 2,075건은 PNU로 바꿀 수 없어 뺐고, 49,074행(41,458개 지번)이 남았다.
2. **규칙**: 현행 대장에 건물이 없는 지번에서, 거래일이 그 지번의 가장 늦은 말소일 이전이면 제외한다.
3. **말소일 뒤의 거래는 남긴다.** 같은 지번에 새로 지어 아직 대장에 오르지 않은 건물의 거래이기 때문이다. 예: 화곡동 163-7은 옛 서진빌라가 2022-08에 말소됐고, 2026년에 새 건물이 섰다. 이런 거래는 옛 건물 공시가격으로 채운 층수·세대수를 비우고, 출처를 "없음"으로 표시한다.
4. **현행 대장이 있는 지번에는 적용하지 않는다.** 그 경우는 1007_11의 "재건축 전 거래" 규칙이 이미 걸러 두었다. 대장이 있고 거래일이 지금 건물 승인일 전이면서 말소일 전인 거래를 따로 세어 보니 0건이었다.

## 3. 근거

| 확인 | 결과 |
|---|---|
| 대장 없는 지번 114개 중 말소 기록 있음 | **113개**(봉천동 1710-10 하나만 기록 없음, 거래 1건이라 그대로 둠) |
| 말소일 이전 거래 | 523건(최근 3년 119건) — 최근 3년 학습 데이터 14,520건의 0.8% |
| 말소일 뒤 거래(새 건물) | 20건(화곡동 163-7) |
| 같은 건물에서 하루 3건 이상 거래된 비율 | 제외 거래 45.5% vs 나머지 9.2% — 재건축을 위해 건물을 한꺼번에 사들인 거래가 많다 |
| 공시가격 대비 이례 정도(수정 Z 절댓값 중앙값) | 제외 거래 0.65 vs 나머지 0.67 — **가격 자체가 튀지는 않았다** |
| 검증 건물(632개)과 겹침 | 0개 — 검증 대상 자체는 바뀌지 않음 |

- 그래서 제외 이유는 "가격이 이상해서"가 아니라 "이미 없는 건물이고 건물 정보가 근사값이라서"다.
- AI는 처음에 "매집 거래라 가격이 이례적일 것"이라고 했는데, 수치로 확인하니 맞지 않아 정정했다.

## 4. 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 그대로 둠(1007_02) | 거래 수 유지 | 없는 건물의 근사 정보로 학습 |
| 건축년도 2025 이전이면 제외(말소대장 없이) | 키 없이 바로 가능 | 짐작에 기댄 규칙, 신축·재건축 구분이 거침 |
| **말소대장의 말소일로 제외(채택)** | 공문서 근거, 새 건물 거래는 살림 | 서울 열린데이터광장 키가 필요하고 서울 전체를 받아야 함(약 15분) |
| 폐쇄말소대장의 옛 건물 정보로 채워 남김 | 거래 수 유지, 정보 정확 | 이미 없는 건물이라 예측에 쓸 일이 없고, 작업량 대비 얻는 것이 작음 |

## 5. 대안으로 바꾸는 조건

- 서울 밖으로 권역을 넓히면 → 해당 시·도의 말소대장 자료가 필요하다. 없으면 건축년도 규칙으로 대신한다.
- 철거 직전 거래 자체를 학습하고 싶다면(재개발 프리미엄 연구 등) → 옛 건물 정보로 채워 남기는 안을 쓴다.

## 6. 결과

- `trades.csv` 33,886건 → **33,363건**. 최근 3년 학습 14,520 → 14,401건. 층 정합성 불일치 표시 17 → 9건.
- 고정 검증 632개 건물, 면적 있음(`outputs/validation_summary.csv`):

| 지표 | A 처음 보는 건물 (전 → 후) | B 같은 건물 거래 있음 (전 → 후) |
|---|---|---|
| 중앙값 오차 | 9.3% → 9.4% | 9.0% → 8.6% |
| MAPE | 13.7% → 13.7% | 13.0% → 13.0% |
| ±20% 적중 | 79.0% → 78.5% | 80.2% → 80.1% |
| 80% 구간 포함 | 82.0% → 82.9% | 79.7% → 80.7% |
| 신뢰도–오차 순위상관 | −0.224 → −0.256 | −0.214 → −0.230 |

- ±20% 적중 A −0.5%p는 632개 중 3개 건물 차이라 우연한 흔들림 범위다. 신뢰도가 오차를 가리는 힘(순위상관)은 두 상황 모두 좋아졌고, 구간별 신뢰도와 실제 적중률도 더 가까워졌다(A 0.6 이하 0.57 → 실제 0.59, 0.7～0.8 0.77 → 0.77).
- 1007_07 성공 기준 5개는 그대로 충족한다.
- 기준선 B1은 거의 같다(A ±20% 71.7% 그대로).
- 보정 표본 10,096건(2,524개 건물), 고정 검증 건물과 겹침 0.
- 다시 만든 것: `calibration.json`, 노트북 01·02·04·05, `outputs/validation_*.csv`·`error_*.csv`·`example_output.csv`·그림.

### 함께 잡은 문제: 검증 건물이 바뀔 뻔했다

- `notebooks/make_01_baseline.py`는 실행할 때마다 지금 거래로 검증 건물을 다시 뽑아 `holdout_pnu.csv`를 덮어썼다.
- 거래가 빠지자 후보 건물이 달라져 같은 시드로도 **632개 중 약 400개가 다른 건물로 바뀌었다**.
- 바로 원래 파일로 되돌리고, 파일이 있으면 읽고 없을 때만 새로 뽑도록 고쳤다. 다시 실행한 뒤 파일이 바뀌지 않은 것을 확인했다.
- 보정은 시작할 때 원래 파일을 읽어서 영향이 없었다(보정 표본과 고정 검증 건물 겹침 0으로 확인).
