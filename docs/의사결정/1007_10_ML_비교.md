- 계기: B1(공시가격 × 실거래/공시 비율, 1007_08)은 공시가격이 반영하지 못한 건물 특성(승강기·연식·층·역 거리 등)을 쓰지 않는다. ML로 이 부분을 더 설명할 수 있는지, 있다면 어떤 모델이 가장 나은지 확인한다

## 1. 비교 대상 — 4계열 × 2방식

- 방법: 같은 변수·같은 검증 틀에서 복잡도가 다른 4계열을 비교한다. 각 계열을 두 방식으로 학습하고, 두 방식의 기하평균도 후보로 둔다

| 계열 | 성격 | 파이프라인 | 그리드 |
|---|---|---|---|
| Ridge | 선형 헤도닉 회귀(전통 감정평가 방식) | 결측 중앙값 채움(+결측 표시) → 표준화 → Ridge | alpha 0.1·1·10·100 |
| KNN | 비슷한 거래 k개의 평균(비교사례법과 같은 발상) | 결측 중앙값 채움 → 표준화 → KNN | k 5·10·20·40 × 균등·거리 가중 |
| RF | 배깅 트리(랜덤포레스트, 트리 200개) | 변수 선택만(결측 그대로) | 잎 최소 2·5·20 × 변수 비율 0.33·0.6 |
| XGB | 부스팅 트리(학습률 0.03 고정) | 변수 선택만(결측 그대로) | 깊이 3·5·7·9 × 트리 300·800·1500 × 잎 최소 가중 5·20 |

| 방식 | 목표값 | 변수 |
|---|---|---|
| 직접 | log(기준일 ㎡당 가격) | 헤도닉 17개: 공시가격 ㎡단가, 면적, 층·지하·상대층·최상층, 연식, 승강기, 지상층수, 세대수, 세대당 주차, 역 거리, 땅값, 좌표, 구 |
| 잔차 | log(기준일 실거래가 ÷ B1 추정) | 헤도닉 + B1 근거 6개(동네 비율·흩어짐, 같은 건물 앞선 거래 비율 차이·건수·흩어짐, B1 비율) |
| 평균 | 직접 × 잔차의 기하평균 | — |

- 근거: "왜 그 모델인가"에 답하려면 단순한 모델부터 비교해야 한다. 선형은 해석 가능한 기준선이고, KNN은 감정평가의 비교사례법을 그대로 옮긴 것이며, RF와 XGB는 트리 계열 중 배깅과 부스팅의 대표다. 잔차 방식은 B1의 설명 틀(공시가격 × 비율)을 유지한 채 보정만 더한다
- 대안: LightGBM·CatBoost — XGB와 같은 부스팅이라 얻는 정보가 적음 / SVR·신경망 — 3만 건 표 데이터에서 트리보다 낫다는 근거가 약하고 설명이 어려움
- XGB 그리드: 1차 실험(깊이 3·5·7, 학습률 0.03·0.1, 트리 300·800)에서 4번 모두 학습률 0.03을 골랐고 깊이 7·트리 800이 그리드 끝이어서, 학습률을 고정하고 깊이·트리 수 범위를 넓혔다

## 2. 검증 틀 — 누수 방지와 세 가지 상황

- 그리드서치: 학습 세트 안에서 건물(PNU) 단위 GroupKFold(5), 기준 MAE(log). 최종 검증 건물 632개는 마지막 비교에만 쓴다
- 학습 행의 B1 근거: 같은 건물은 그 거래보다 앞선 거래만, 동네 통계는 자기 건물을 뺀 폴드로 만든다(예측 때와 같은 조건)
- 상황

| 상황 | 학습 데이터 | 뜻 |
|---|---|---|
| A | 검증 건물 거래 모두 제외 | 처음 보는 건물 |
| B | 검증 건물은 대상 거래 이전 거래만 | 같은 건물 과거 거래가 있는 물건(실제 입력에 가장 가까움) |
| T | 모든 건물에서 2025-09-01 이전 거래만 | **시점 밖 검증**: 1년 전에 만든 모델로 그 뒤 1년(2025-10~2026-10) 거래를 맞힘 |

- 상황 T를 넣은 이유: 새 거래가 쌓이고 가격 수준이 바뀌어도 모델이 버티는지(범용성)를 보려면, 학습 때 없던 기간을 맞혀야 한다. A·B는 학습 데이터가 검증 거래와 같은 기간을 덮어 이것을 재지 못한다. T에서는 시점 지수를 마지막 달 이후 평평하게 이어 붙이므로 그 사이 시장 변동이 그대로 오차가 된다
- 상황 T의 한계: 공시가격은 2026년 값 하나뿐이라 2025-08 이전 학습에도 2026 공시가격(2026-04 공시)을 쓴다. 모든 모델이 같은 조건이라 모델 간 순위 비교에는 영향이 작지만, 절대 오차는 실제보다 조금 낙관적이다
- 시점 지수 수정: T처럼 학습 거래가 기준 달보다 일찍 끝나면 마지막 달의 원값(이동평균 전)이 이어 붙던 문제를 고쳐, 이동평균 값을 이어 붙이게 했다. 학습 거래가 기준 달까지 있는 평소 실행은 지수가 그대로임을 확인했다

## 3. 선정 기준 (결과를 보기 전에 정함)

1. **허용오차 적중률**: ±20% 적중률(1007_07 목표 지표)과 중앙값 오차율
2. **꼬리 오차**: 평균 오차율(MAPE) — 크게 틀리는 경우가 적은지
3. **범용성**: 세 상황(A·B·T) 모두에서 상위권인지. 한 상황에서만 좋은 모델보다 어느 상황에서도 크게 밀리지 않는 모델을 고른다. 특히 T(시간이 지나도 버티는지)
4. **차이가 우연이 아닌지**: 건물 재표본 부트스트랩 95% 구간. 차이가 구간 안이면 같은 성능으로 보고, **더 단순하고 설명 가능한 모델**을 고른다
5. **운영**: predict.py 실행 시간(30분 제한), 의존성, 근거 문장으로 설명 가능한지

- 근거: 같은 검증 세트로 여러 모델을 고르면 우연히 좋게 나온 모델을 고를 위험(선택 편향)이 있다. 기준을 먼저 정하고, 작은 차이는 단순성으로 결정해 이 위험을 줄인다

### 4.4 시간이 지나면(상황 T)

- 모든 모델이 낮게 추정한다: log 오차 중앙값 B1 −3.5%, XGB-직접 −4.1%, XGB-잔차 −3.3%, XGB-평균 −3.8%. 학습 마감 뒤 1년간 오른 가격이 그대로 오차가 된 것이다

- 직접 방식이 더 낮게 추정한다 — 트리 모델은 학습 범위 밖 가격 수준을 외삽하지 못하고, 잔차 방식은 매년 갱신되는 공시가격에 붙어 있어 덜하다

## 5. 결정

- **최종 모델: XGB-평균** = √(XGBoost 직접 추정 × B1 × exp(XGBoost 잔차)). 공시가격이 없는 물건은 잔차 대신 B1(㎡단가) 추정을 쓴다
- 근거(§3 기준 순서)
  1. 허용오차: ±20% 적중률 A·B 1위, T 공동 1위(RF-평균과 같음). 중앙값 오차는 A 3위(XGB-직접 9.7%, RF-직접 10.0%보다 0.3%p 이내), B 2위(XGB-잔차 9.3%), T 1위
  2. 꼬리: MAPE는 1~3위권이고 1위와 차이가 0.1~0.3%p
  3. 범용성: 세 상황 모두 상위권(가장 나쁜 순위 2.3, 13개 중 가장 좋음). 한쪽 방식만 쓰면 직접은 B·T, 잔차는 A에서 유의하게 밀린다
  4. 단순성: 비슷한 성능의 RF-평균은 복잡도가 같다(트리 앙상블 두 개). 더 단순한 Ridge·KNN은 유의하게 나쁘다
  5. 운영: 설명은 "공시가격 기반 추정(B1)을 XGBoost로 보정한 값과 XGBoost가 건물·입지로 직접 낸 값의 평균"
- 하이퍼파라미터: 상황 B(실제 입력에 가장 가까움)의 최적값 — 직접 깊이 5·트리 800·mcw 20, 잔차 깊이 9·트리 300·mcw 20(학습률 0.03 고정)
- 대안과 바꾸는 조건
  - RF-평균: XGB-평균과 차이가 대부분 우연 범위 안. xgboost 설치가 평가자 환경에서 문제가 되면 scikit-learn만으로 되는 RF-평균으로 바꾼다
  - XGB-잔차 단독: 설명이 가장 쉽지만 처음 보는 건물(A)에서 유의하게 나쁘다. 실제 입력이 대부분 같은 건물 거래가 있는 물건이라고 확인되면 검토
  - B1 유지: ML이 실행 시간·재현성 문제를 일으키면 되돌린다
- 운영 원칙(상황 T에서 나온 것): predict.py는 실행할 때마다 최신 거래로 시점 지수와 모델을 다시 맞춘다. 새 거래가 쌓이면 다시 실행하는 것만으로 반영된다

- 시점 지수는 학습 세트로 맞춘다(검증 대상 거래 하나가 구·월 중앙값에 주는 영향은 무시할 만함)
- 상황 T는 2026 공시가격을 2025 학습에도 쓴다(§2)
- 구간·신뢰도(1007_09)는 B1 오차로 보정한 것이라 최종 모델로 다시 보정했다 → [1007_09 §5](1007_09_구간_신뢰도_보정.md)

## 7. 적용

- predict.py: B1과 같은 학습 거래·시점 지수로 XGBoost 직접·잔차를 실행할 때마다 학습(하이퍼파라미터 `FINAL_PARAMS` 고정) → 기하평균. 20건 약 25초(이전 B1만 약 6초), 두 번 실행 출력 동일, 표본 20건·예외 10건 규격 통과
- 연결 검증: 같은 경로(`run_holdout(ml=True)`)로 최종 검증을 다시 추정 → 상황 B는 비교 실험의 XGB-평균과 같다(상대 차이 최대 2e-16). 상황 A는 실험에서 A 자체 최적값을 썼고 적용은 B 최적값으로 고정해 조금 다르다(±20% 적중 75.5% 같음, 중앙값 오차 10.03% → 10.05%)
- 근거 문장: `공시가격 0.89억 × 실거래/공시 비율 1.66(같은 건물 7건+법정동, 기준일 시점보정) = 1.47억, 건물·입지 보정 ×1.02(XGBoost 잔차 1.50억·XGBoost 직접 1.52억 평균)`
- 의존성: xgboost·scikit-learn을 실행 의존성으로 옮기고 requirements.txt 재생성(Linux에서는 xgboost가 GPU 통신 라이브러리 nvidia-nccl도 함께 설치 — 용량이 크지만 CPU로 동작)
