# 1007_12 실행 중 조회 — 수집 데이터에 없는 지번

- 상태: 확정 (2026-10-07, 사용자 결정)
- 코드: `src/live_lookup.py`(`LiveLookup`), `src/avm.py` `estimate(live=)`, `predict.py`
- 계기: 문서 점검 중 과제 입출력 규격의 요구(미리 모은 데이터는 함께 내고, 거기에 없는 물건은 실행하면서 조회할 것)를 구현하지 않았음을 발견. 그때까지 predict.py는 외부 API를 전혀 부르지 않았고, 그 판단을 적은 의사결정 문서도 없었다

## 1. 무엇이 빠질 수 있나

| 정보 | 수집 범위 | 평가 후보 건물 3,159개 중 없음 | 빠지면(조회 전) |
|---|---|---|---|
| 필지 좌표·공시지가 | 3개 구 전체 필지 123,615개 | 0 | — |
| 공시가격(호별) | 실거래가 있던 지번 9,922개 | 5(0.2%) | ㎡단가 추정, 신뢰도 0.10 |
| 건축물대장 표제부 | 실거래가 있던 지번 | 5 | 승강기·연식 등 결측 → XGBoost 보정이 약해짐 |

- 위험이 큰 경우: 수집(10-06) 뒤에 신고된 거래만 있는 새 건물. 참고로 평가 후보 중 첫 거래가 2026-08 이후인 건물이 66개(2.1%)

## 2. 방법

- 입력 지번이 수집 데이터에 없을 때만 조회한다. 수집된 지번은 부르지 않는다(기존 표본 20건·예외 10건 출력 바이트 동일)
  - 공시가격: VWorld `getApartHousingPriceAttr`, 2026 → 2025 → … → 2020 순서로 가장 최근 연도(수집 때와 같음)
  - 표제부: 건축HUB `getBrTitleInfo`. 현행 대장에 건물이 없으면 1007_02처럼 공시가격의 층·호 수로 지상층수·세대수만, 연식은 그 지번 거래의 건축년도 중앙값
- 정제는 수집 데이터와 같은 규칙: 공시가격은 `build_apt_price.py`(중복 제거·`ho_key`), 표제부는 `build_bld_title.py`(공동주택 동을 지번 단위로 합침)와 `ml.load_buildings`(1007_11 결측 규칙)
- 키(`VWORLD_API_KEY`·`DATA_GO_KR_API_KEY`)가 없거나 조회가 실패하면 조회 없이 추정을 계속하고 `basis`에 이유를 적는다(예: `공시가격 실행 중 조회 못 함(키 없음)`). 평가 환경에 키가 없어도 predict.py는 그대로 돈다
- 건축HUB의 간헐적 503(SERVICETIMEOUT)은 2·4·8초 기다렸다가 최대 4번 시도. 조회 시간 합이 10분을 넘으면 이후 지번은 조회하지 않는다(20건 30분 제한 안에서 모델 학습 시간을 남김)
- 받은 값은 그 실행의 메모리에서만 쓰고 파일로 저장하지 않는다

## 3. 근거

- 과제 규격(반드시 준수 묶음)에 들어 있는 요구이고, 입력 물건을 미리 알 수 없다는 전제(대상 범위)와 맞닿아 있다
- 공시가격이 있으면 공시비율 방식(검증 632건 기준 중앙값 오차 9.5～9.9%)을 쓸 수 있고, 없으면 ㎡단가 방식(보정 표본 ±20% 적중 10%)으로 떨어진다 — 조회 여부가 정확도를 크게 가른다
- 대안: 그대로 두고 한계로 적기 — 영향 범위는 작지만(0.2%) 규격 요구를 채우지 못함 / 수집 범위를 3개 구 전체 지번으로 넓히기 — 12만 필지 대부분이 다세대가 아니라 호출 낭비가 크고, 수집 뒤 생긴 건물은 여전히 못 덮음
- 바꾸는 조건: 평가 환경에 키를 넣을 수 없다는 것이 확인되면 조회는 의미가 없으므로, 그때는 수집 범위를 넓히는 쪽을 검토

## 4. 결과(시험)

| 시험 | 방법 | 결과 |
|---|---|---|
| 수집된 지번은 그대로 | 표본 20건·예외 10건 | 출력 바이트 동일, API 호출 없음 |
| 조회 값이 수집 데이터와 같은가 | 수집된 지번 15개(여러 동·보충 연도 공시·대장 건물 없음·세대수 0 포함)를 메모리에서 지운 뒤 실행 중 조회 | 공시가격·건물 변수·추정값 15개 모두 일치. 조회 시간 지번당 2.4～35초(건축HUB 503 재시도 포함), 합 146초 |
| 수집 데이터에 없는 실제 빌라 | 공시가격·거래가 수집되지 않은 다세대 3개(화곡동 2·봉천동 1)를 predict.py로 | 키 있음: 공시비율 방식, 신뢰도 0.65～0.72, 28초 / 키 없음: ㎡단가 방식, 신뢰도 0.10, basis에 "키 없음", 20초. 두 경우 모두 규격 통과. 추정값 차이 최대 50%(키 없음이 높음) — 실거래가 없어 정답은 모름 |

- 한계: 실행 중 조회한 물건의 정확도는 따로 검증하지 못했다(그런 물건은 실거래가 없어 정답이 없다). 같은 추정 경로를 쓰므로 최종 검증 수치에 준한다고 본다
