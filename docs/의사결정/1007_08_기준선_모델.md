## 1. 시점 지수

- 방법: 구별로 log(실거래가 / 2026 공시가격)의 월 중앙값 → 3개월 이동평균. 2026-08을 기준(1.0)으로 두고 09·10월은 신고기한 전이라 쓰지 않는다
- 근거: 공시가격이 위치·면적·연식·층을 반영하므로, 달마다 거래된 건물 구성이 달라도 시장 수준만 비교할 수 있다(1007_04에서 이 비율의 집단 내 퍼짐이 가장 작음을 확인). ㎡당 단가 중앙값으로 만들면 그 달 거래된 건물의 연식·입지 구성에 따라 출렁인다
- 결과(2026-08 = 1.0): 2020-10 강서 0.92·관악 0.84·강남 0.78 → 2022-10 강서 1.04(고점) → 2026-08 1.0. 강서는 2022 고점보다 낮고, 관악·강남은 2026이 가장 높다
- 대안: 반복매매지수(같은 호의 재거래) — 실거래에 호가 없어 같은 호 재거래를 특정하기 어려움 / 헤도닉 회귀 지수 — 변수 정리가 끝난 뒤 비교 후보

## 2. 기준선 두 개

| 기준선 | 방법 |
|---|---|
| B0 ㎡단가 | 시점 보정 ㎡당 단가 중앙값 × 전용면적 |
| B1 공시비율 | 같은 호(층·면적) 공시가격 × 시점 보정 실거래가/공시가격 비율 |

공통: 근거는 같은 건물 → 법정동(거래 20건 이상) → 구 순서. 같은 건물 사례가 n건이면 `(n·건물 + 2·법정동)/(n + 2)`로 법정동 쪽으로 당긴다 — 사례가 1~2건뿐인 건물에서 한 거래가 결과를 좌우하지 않게 하고(1006_03의 취지와도 맞음), 사례가 많을수록 건물 값에 가까워진다.

| 상황 | 기준선 | 중앙값 APE | MAPE | ±10% | ±20% | 80% 구간 포함률 |

## 4. 판단

- **B1을 predict.py 1차로 채택**: 처음 보는 건물에서 중앙값 오차가 B0의 절반 이하(26.2% → 11.7%). 공시가격이 같은 동네 안의 건물·호 차이를 이미 담고 있어서, 비율만 지역에서 빌려 와도 ㎡당 단가보다 훨씬 정확하다. 같은 건물 과거 거래가 있으면 더 좋아진다(B0은 26.2 → 15.9%로 크게, B1은 11.7 → 11.1%로 작게 — B1은 처음 보는 건물에서도 이미 강하다)
- **목표(1007_07) 대비**: 실패율 0%(권역 안 표본 20건)·신뢰도 단조성(같은 건물 10.4% < 법정동 14.0% < ㎡단가 38%)은 충족. 중앙값 APE 11.1%(목표 10%), ±20% 73.7%(목표 75%)는 조금 못 미침. **80% 구간 포함률 60~65%로 구간이 너무 좁음**(목표 70~90%)
- **강남이 약함**: 고가·대형·고급 빌라가 섞여 비율 퍼짐이 크다 → 보정 단계에서 강남은 면적·가격대 구분 또는 반경 비교사례 우선 검토

## 5. 남은 과제 (다음 단계)

1. 구간·신뢰도 보정: 홀드아웃의 실제 log 오차 분포로 근거 수준별 구간 폭을 다시 정하고, 신뢰도는 실제 오차가 작은 순서로 매긴다. 지금 신뢰도는 근거 수준만으로 정해 값이 0.65·0.80 두 개에 몰려 있다
2. 비교사례 보정(1006_02): 반경 내 유사 사례, 층·연식·승강기·역 거리 보정 → B1 대비 개선 여부
3. 오차 큰 사례 분석: 상위 사례는 실제 거래가가 같은 건물 비율보다 크게 낮은 경우가 많음(예: 대치동 공시 1.59억, 같은 건물 비율 2.39 → 추정 3.8억, 실거래 1.8억) — 낮은 이상치 기준(−3.5) 밖의 저가 거래이거나 같은 지번 안 다른 성격의 호. 원인 확인 필요

## predict.py 1차 동작

- 입력 → `parse_address`(시군구·법정동·지번 → PNU, 권역 밖·해석 불가는 fail) → 필지·공시가격·거래 어디에도 없는 지번은 fail → 공시가격 호 찾기(`ho_key` → 같은 층·면적 → 같은 층 근사) → 면적이 비면 공시가격 호 면적 → 같은 건물 거래 면적 → 법정동 면적 순 → B1(공시가격 없으면 B0)
- 외부 API를 부르지 않는다. 실행할 때마다 정제 데이터로 다시 맞춘다(별도 모델 파일 없음) → 갱신: 수집 데이터에 없는 지번만 실행 중 조회([1007_12](1007_12_실행_중_조회.md))
- 검사: `tests/sample_input.csv` 20건 ok 20·규격 통과·약 21초 / `tests/edge_input.csv` 10건 — 권역 밖 2·주소 해석 불가 2·필지 없음 2는 fail, 지하 표기(`B1`·`지하1`)·`301호`·`번지`·약식 시군구는 정상 처리

## 개발 중 발견·수정한 오류

- 호 표기 함수가 (호 키, 동 표시) 두 값을 돌려주는데 하나로 받아 비교 → 호가 있는 입력 18/20건이 처리 오류. 홀드아웃은 호 없이 넣어 드러나지 않았고, 입력 표본 실행에서 발견
- 규격 검사기가 형식만 보고 "통과"를 냄 → 예상 못 한 처리 오류와 `--expect-ok`(전부 ok여야 하는 입력)를 위반으로 잡도록 강화
- 존재하지 않는 지번도 법정동 평균으로 추정해 냄 → 필지·공시가격·거래 어디에도 없으면 fail
- (재검증) 입력 호로 찾은 공시가격 호의 면적이 입력 면적과 다르면 호 표기를 잘못 맞춘 것으로 보고 층·면적으로 다시 찾도록 보완 — 표본 16번(호 `3`, 같은 층에 `3`으로 통일되는 호가 여럿)에서 작동, 신뢰도 0.75로 표시
- (재검증) 1007_07 문서의 검증 기간·후보 수(2025-10-01, 3,188개)가 코드(기준일 12개월 전 다음 날 2025-10-07, 3,159개)와 달라 문서를 코드에 맞춤. 검증 건물 632개·결과는 그대로
