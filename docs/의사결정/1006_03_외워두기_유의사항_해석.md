# 1006_03 "외워 두기" 유의사항 해석과 같은 건물 거래 처리

- 상태: 확정 (사용자 결정)

## 배경

과제 유의사항(요약): 학습 데이터에 특정 물건을 외워 두는 방식은 평가에서 제외된다.
블라인드 검증 물건은 권역 내 최근 12개월 안에 실거래가 있는 다세대에서 뽑히므로, 그 거래가 우리 수집 데이터에 이미 있을 수 있다.

## 검토한 안

"같은 호로 보이는 거래" = 같은 지번 + 같은 층 + 같은 전용면적의 과거 거래 (실거래에는 호가 없음)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 같은 호로 보이는 거래가 있으면 그 값을 시점 보정해 그대로 사용 | 그 물건의 실제 거래라 정확도가 가장 높음 | 입력과 같은 거래를 찾아 꺼내는 분기가 되어 "외워 두기"로 보일 수 있음. 같은 호 거래가 없는 물건과 처리가 달라져 일관성이 떨어짐 |
| B | 근거 중 하나로 쓰되 비중 상한을 둠 | 실무 감정평가처럼 여러 사례를 함께 봄. 한 건이 결과를 좌우하지 않음 | 상한 값을 따로 정하고 검증해야 함. "같은 호"를 실제로 구분할 수 없는데 별도 규칙을 두는 셈 |
| C | 같은 호로 보이는 거래는 비교사례에서 제외 | 외워 두기 의심의 여지가 없음 | 가장 좋은 비교사례를 버려 정확도가 떨어짐. 같은 층 다른 호 거래까지 함께 빠짐 |
| 학습에서 최근 12개월 제외 | 최근 12개월 거래를 학습·비교사례에서 뺌 | 검증 물건의 거래가 모델에 들어갈 여지를 없앰 | 비교사례법은 예측 시점에 데이터를 검색하므로 학습에서만 빼면 효과가 없고, 비교사례에서도 빼면 기준일 시세 정보를 잃어 정확도가 크게 떨어짐 → 제출 모델에는 부적합. 단, **자체 검증(train/test)에는 이 방식으로 분리**한다 |

## 결정 과정

1. AI가 유의사항과 검증 물건 추출 조건을 근거로 위험을 제기하고 B를 추천
2. 사용자 질문: "최근 12개월을 학습에서 빼면 되지 않나" → 자체 검증과 블라인드 평가가 다른 것, 비교사례 검색은 학습과 별개라는 점을 정리(위 표 마지막 행)
3. 사용자 판단: 유의사항이 막는 것은 코드에 특정 물건을 외워 두는 방식이고, 같은 층 다른 호와 구분도 불가능하므로 같은 호 거래를 따로 다룰 이유가 없다 → AI가 위험을 과대평가했음을 인정하고 아래로 결정

## 결정

**같은 호로 보이는 거래를 특별 취급하지 않는다.** 같은 건물의 다른 거래와 똑같이 시점·층 보정 후 비교사례 가중평균에 넣는다.

근거 (사용자 판단):
1. 유의사항이 막는 것은 **코드에 특정 물건의 답을 넣어 두거나 찾아 꺼내는 방식**이다. 모든 입력에 같은 산출 로직을 적용하면, 결과가 실거래와 가깝더라도 외워 둔 것이 아니다
2. 실거래에는 호가 없어 "같은 호"와 "같은 층 다른 호"를 구분할 수 없고, 같은 건물·같은 층이면 가격 차이도 작다
3. 같은 건물의 과거 거래는 감정평가 실무에서도 가장 우선하는 비교사례다
4. 블라인드 검증이 공공데이터에 아직 공개되지 않은 거래나 평가 측 자체 자료로 이루어질 수도 있다

## 지킬 것

- 코드에 특정 지번·호의 가격을 넣거나, 입력과 같은 거래를 찾아 그 값을 바로 반환하는 분기를 만들지 않는다
- `basis`에 근거를 그대로 적는다(예: `동일건물 사례 2건 포함`)
- 자체 검증은 train/test를 나눠서 한다. 최근 12개월 거래가 있는 건물 일부를 **건물 단위로** 학습·비교사례에서 모두 빼고 측정하고, 같은 건물 과거 거래를 남긴 경우도 함께 보고한다
- PPT에 이 처리 방식과 두 검증 결과를 함께 싣는다
