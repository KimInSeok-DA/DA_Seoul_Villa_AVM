# 1007_03 공시가격 정제: 보충 연도, 중복 제거, 호 표기 통일

- 상태: 확정 (2026-10-07, 수집 완료 후 점검·보완·중복 전처리를 사용자가 맡김)
- 코드: `src/build_apt_price.py` → `data/processed/apt_price.csv`
- 출처: 국토교통부 공동주택가격정보(VWorld 제공, data.go.kr 15124003). 이용허락범위 "제한 없음" → 정제본을 저장·공개해도 된다

## 1. 2026년 공시가가 없는 지번은 과거 연도로 보충

- 사실: 9,928개 지번 중 196개는 2026년 공시가격이 없음(응답 형식 `{"response": {"totalCount": "0"}}`). 대부분 2021년 전후에만 거래된 건물
- 결정: 2025 → 2020 순으로 조회해 가장 최근 연도를 쓴다. 190개 확보, 6개 미확보
- 근거:
  - 이 지번들의 거래(2020~2025년)를 학습·비교사례에 쓰려면 같은 건물의 호별 상대가격이 필요하다
  - 2020년까지만 거슬러 가는 이유: 실거래 수집 시작이 2020-10이라 그보다 오래된 공시는 쓸 거래가 없다
- 주의: 연도마다 공시가격 현실화 수준이 달라 실거래/공시 비율이 연도에 따라 다르다 → `stdr_year` 열을 남겨 두고, 비율은 연도를 구분해 계산한다

## 2. 중복 제거

- 사실: VWorld는 모든 응답에서 같은 행을 정확히 2번씩 준다(5,920개 지번 전부 2배). 보충분 44개 지번은 같은 호가 갱신일(`lastUpdtDt`)만 다르게 2번 온다
- 결정: 완전히 같은 행은 1개만, 갱신일만 다른 행은 최신 갱신 1개만 남긴다
- 근거: 갱신일 외 모든 값(공시가격·면적·층)이 같은지 코드에서 확인하고(값이 다른 그룹 0개), 다르면 멈추게 했다. 결과 (지번, 동, 호, 연도) 중복 0
- 결과: 213,123행 → 107,236행

## 3. 호 표기 통일 (`ho_key`)

- 사실: 원본 호 표기가 제각각이다 — `301`, `3층301호`, `301(3층)`, `일층(101)`, `B01`, `비01`, `지층지1`, `지하층비01`, `지상2층에이세대`, `1층가`, `101동201`, `나201`, `제101`, `2-1` 등
- 결정: 규칙으로 통일한 `ho_key`와, 호 앞 동 표시를 떼어 낸 `ho_prefix` 열을 만든다. 지하는 `B`+번호(`B1`), 지상은 숫자(`301`), 층+문자는 `1가`·`2A`
- 근거:
  - 과제 입력 `ho`(예: `301`)를 같은 건물의 공시가격 호와 맞춰야 호별 가격 차이를 반영할 수 있다
  - 입력 `ho`에도 예측 시 같은 함수를 적용한다
- 검증:
  - 표기별 테스트 26개 통과
  - 같은 지번·동·층 안에서 서로 다른 호가 같은 키가 되는 충돌을 세어 규칙을 고침: 376행 → 271 → 100 → 2행(1개 지번)
  - 표준형(`301`·`B1`·`1001` 등) 99.5%
- 한계: 남은 0.5%는 문자형 표기라 입력 `ho`와 정확히 맞지 않을 수 있다 → 예측 시 맞는 호가 없으면 같은 층·비슷한 면적의 호로 대신한다(모델 단계에서 구현)
