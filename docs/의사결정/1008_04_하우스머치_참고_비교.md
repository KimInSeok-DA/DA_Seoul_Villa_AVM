# 1008_04 하우스머치 참고 비교 (9건)

- 상태: 정리 (2026-10-08). 참고 비교만 하고 모델은 바꾸지 않는다
- 코드: `src/compare_housemuch.py` — 하우스머치 조회값은 `_private/housemuch_values.csv`에서 읽고 건별 결과도 `_private/`에 쓴다(저장소 제외)
- 원칙: 상용 시세 결과는 **입력·학습에 쓰지 않는다**(과제 조건, AGENTS.md). 자체 검증의 참고로만 쓰고 출처를 밝힌다
- **공개 범위**: 하우스머치 이용약관(주식회사 공감랩, 2021-12-05 시행)은 추정시세정보의 저작권이 회사에 있고(제4조 ③), 서비스와 정보의 복제를 금지한다(제9조 ④ ⑥). 출처 표시 인용의 예외 조항은 없다. 과제도 사이트 약관을 지키라고 한다. 그래서 **건별 하우스머치 값(시세·상하한·건별 오차·가격신뢰등급)은 공개 저장소에 두지 않고, 요약 통계만 쓴다**(사용자 결정 2026-10-08)
- 조회 화면 PDF는 개인 참고용으로 `하우스머치 비교/`에 두고 저장소에는 올리지 않는다(`.gitignore`)

## 1. 왜

블라인드 평가가 실거래가 대비 오차와 함께 **하우스머치 대비 오차**를 본다. 상용 서비스가 같은 물건에 어느 정도 값을 내는지 감을 잡으려고 소수만 직접 조회했다.

## 2. 방법

1. **물건 고르기**: 최종 검증 건물(632개) 중 2026년에 거래된 것에서 권역마다 3건, 우리 신뢰도 높음(0.8 초과)·중간(0.7～0.8)·낮음(0.7 이하)을 1건씩 무작위로 골랐다(시드 7). 직거래 2건이 섞였다.
2. **우리 값**: 상황 B(같은 건물 과거 거래 있음)·면적 있음의 **검증 추정**을 쓴다. 비교 대상 거래를 빼고 낸 값이다.
3. **하우스머치 값**: 사용자가 사이트에서 같은 지번·층·면적의 호를 직접 조회했다(2026-10-08). 추정 기준일은 2026-09-01이고, 중위시세와 상하한시세를 옮겨 적었다. 자동 수집은 하지 않았다(약관). 9건을 조회한 뒤 하루 조회 한도에 걸렸다.
4. **기준**: 신고된 실거래가.

- 이 9건에서는 **하우스머치가 더 가깝다.** 다만 하우스머치는 **비교 대상 거래를 알고 낸 값**일 수 있다. 조회 화면의 "본건 거래사례"에 비교 대상 거래가 그대로 나온다(화곡동 811-9에서 확인). 우리 추정은 그 거래를 빼고 냈다. 그래서 정확도를 겨루는 비교가 아니다. 하우스머치 기준일(09-01) 뒤 거래인 화곡동 362-79 1건만 하우스머치가 확실히 모르는 상태였고, 그 건도 하우스머치가 더 가까웠다
- **직거래 2건은 둘 다 높게 추정했고 우리 오차가 더 크다.** 크게 틀린 원인이 공시 대비 이례적인 거래라는 1007_13의 결과와 같다
- **신뢰도**: 우리 신뢰도가 가장 낮은 역삼동(0.58)의 오차가 중개거래 중 가장 컸다(+23%)
- **범위**: 하우스머치 상하한시세는 우리 80% 구간보다 훨씬 좁아 실거래가가 3건만 들어갔다. 우리 80% 구간은 7건이 들어갔다

## 4. 이 비교로 하지 않는 것

- 하우스머치 값을 학습·보정·입력에 쓰지 않는다. 9건에 맞춰 모델을 고치지 않는다(과적합, 과제 조건 위반).
- 9건은 표본이 작아 성능 차이를 일반화하지 않는다.

## 5. 대안으로 바꾸는 조건

- 평가 뒤 하우스머치 대비 오차가 공개되면 → 차이가 큰 유형(직거래로 의심되는 싼 거래, 강남 고가 등)을 찾아 공공 데이터로 보완할 수 있는 변수를 검토한다.
