# 1008_01 행정동 이름 입력 처리

- 상태: 적용 (2026-10-08)
- 코드: `src/build_admin_dong.py`(연계표 생성), `src/avm.py`의 `parse_address`·`dong_key`
- 데이터: `data/reference/행정동_법정동_행정안전부_20260930.csv`
- 시험 입력: `tests/admin_dong_input.csv`

## 1. 문제

입력의 `dong`은 법정동(화곡동·봉천동·신림동 등)을 가정했다. 그런데 사람들은 생활에서 **행정동**(화곡1동, 낙성대동, 개포2동 등)을 더 자주 쓴다. 지금까지는 행정동 이름이 들어오면 "법정동이 없음"으로 fail이 됐다(1007_08에 남은 과제로 기록).

블라인드 평가가 **산출 실패 건수**를 보기 때문에, 입력 표기 차이로 실패하는 것은 직접 손해다.

## 2. 방법

1. **연계표**: 행정안전부 주민등록 주소코드 `jscode20260930.zip`에 들어 있는 `KIKmix`(행정동–법정동 연계)를 쓴다. 3개 구, 말소되지 않은 행만 남겼다. 결과는 행정동 63개, 연계 87행이다.
2. **찾는 순서**
   1. 법정동 이름에 맞는 것이 있고 그 법정동에 지번이 있으면, 그 법정동을 쓴다(지금과 같음).
   2. 없으면 행정동으로 보고 연계표에서 법정동 후보를 찾는다.
   3. 후보가 여러 개면, 그 지번에 다세대·연립(공시가격이나 거래)이 있는 법정동을 고른다. 그래도 정해지지 않으면 필지가 있는 법정동을 고른다.
   4. 하나로 정해지지 않으면 fail로 처리하고, 후보 법정동을 사유에 적는다.
3. **표기 통일**: 띄어쓰기를 없애고 "화곡제1동"과 "화곡1동"을 같게 본다.
4. **근거 표시**: `basis` 끝에 "행정동 낙성대동 → 법정동 봉천동"을 붙인다. 신뢰도는 바꾸지 않는다. 법정동이 정해지면 추정 과정이 법정동 입력과 완전히 같기 때문이다.
5. **강서구 권역 확인**: 화곡동만 받는 규칙은 법정동을 정한 **뒤에** 확인한다. 우장산동은 화곡동과 내발산동에 걸치는데, 화곡동 지번이면 통과하고 내발산동 지번이면 권역 밖으로 처리한다.

## 3. 근거

- **공식 연계표**: 행정동과 법정동의 관할 관계는 행정안전부가 고시하는 공식 자료다. 키 없이 내려받을 수 있다. 시행일 2026-09-30본이라 기준일(2026-10-06) 시점에 맞는다.
- **겹침 규모**:
  - 3개 구 행정동 63개 중 15개가 법정동 여러 개에 걸친다.
  - 이런 행정동 아래의 다세대·연립 지번 중 후보 법정동 두 곳 이상에 같은 지번이 있는 경우는 **2건**이다. 둘 다 염창동(염창·가양)이라 평가 권역 밖이다.
  - 평가 권역 안에서는 지번으로 항상 하나로 정해진다.
- **법정동 우선**: 강남 "신사동"처럼 행정동과 법정동 이름이 같은 경우가 있다. 과제 입력은 법정동을 가정하므로 법정동을 먼저 찾는다.

## 4. 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 지금처럼 fail | 단순 | 행정동 입력은 전부 실패 |
| **연계표 + 지번으로 법정동 고르기(채택)** | 공식 자료, 평가 권역에서 모호한 경우 0건 | 연계표를 따로 관리해야 함(행정동 개편 때 갱신) |
| 도로명주소·좌표 API로 주소 해석 | 어떤 표기든 처리 | 실행 중 외부 조회와 키가 필요하고, Kakao는 결과 저장 금지(1006_04) |

## 5. 대안으로 바꾸는 조건

- 입력에 도로명주소가 들어오는 경우가 생기면 → 주소 API 해석을 추가한다.
- 행정동 개편이 생기면 → 새 `jscode` 파일로 `python src/build_admin_dong.py`를 다시 실행한다(파일 이름의 날짜를 바꾼다).

## 6. 결과

  - `tests/sample_input.csv` 20건: 출력이 바뀐 것 없음, 규격 통과.
