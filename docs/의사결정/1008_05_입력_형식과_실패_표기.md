# 1008_05 입력 파일 형식 허용 범위와 실패 행 표기

- 상태: 확정·반영 (2026-10-08, 사용자 결정)
- 코드: `predict.py` `read_input`, `src/avm.py` `parse_floor`·`estimate`(호·면적 읽기), `tests/check_output.py`
- 계기: 제출 전, 과제 원문의 실행 명령(`python predict.py --input input.csv --output output.csv`) 그대로 평가자 입력이 돌아가는지 다시 점검. 모델이 좋아도 입력을 못 읽으면 20건 모두 실패가 된다

## 1. 입력 파일 형식

**확인한 문제**: 엑셀에서 CSV로 저장하면 한글 윈도우는 CP949로 저장한다. 기존 코드는 UTF-8로만 읽어서 이런 파일은 시작하자마자 오류로 멈추고 `output.csv`도 만들지 않았다(직접 만든 CP949 파일로 재현).

- 방법: UTF-8(BOM 있음·없음)로 읽고 실패하면 CP949로 읽는다. 컬럼 이름은 앞뒤 공백을 빼고 소문자로, 값은 앞뒤 공백을 뺀다. 엑셀이 숫자로 바꾼 표기도 받는다: 층 `3.0`, 호 `301.0`, 면적 `42.5㎡`(앞의 숫자만)
- 근거: 과제 원문은 입력 형식(컬럼 이름·예시)만 정하고 인코딩은 정하지 않았다. 평가자가 엑셀로 20건을 만들 가능성이 있다. 읽기 단계의 실패는 한 행이 아니라 전체 실패라 비용이 가장 크다
- 대안: UTF-8만 받고 README에 "UTF-8로 저장"이라고 적기 — 평가자가 README를 안 볼 수 있어 위험이 남는다
- 확인(`tests/excel_cp949_input.csv`: 표본 20건을 CP949·컬럼 순서·대소문자 바꿈·공백·`3.0`·`301.0`·`㎡` 표기로 저장): 표준 입력과 출력이 완전히 같음. 표본·예외·행정동·예시 입력의 ok 행 출력도 수정 전과 같음(검증 수치 변화 없음)

## 2. 실패 행의 status

과제 원문은 status를 "ok, 산출 불가 시 fail과 사유"로만 적었다. 기존 출력은 `status = "fail: 권역 밖(…)"`처럼 status에 사유를 붙였다.

| 선택 | status | 사유 | 평가 자동화가 `== "fail"`로 셀 때 | `startswith("fail")`·`!= "ok"`로 셀 때 |
|---|---|---|---|---|
| 기존 | `fail: 사유` | status·basis | 안 잡힘 | 잡힘 |
| **채택** | `fail` | basis | 잡힘 | 잡힘 |

- 결정: status는 `ok`·`fail` 두 값만, 사유는 basis에(사용자 결정). 어느 방식으로 세도 실패로 잡히고 사유도 남는다
- 대안으로 바꾸는 조건: 평가 측이 status 칸에 사유를 요구한다고 알려 오면 기존 형식으로 되돌린다(`predict.py` 한 줄)

## 3. 규격 검사 명령

README의 규격 검사가 `tests/sample_input.csv`를 가리키고 있어, 평가자가 자기 `input.csv`로 돌린 뒤 그대로 검사하면 "id가 입력과 다름"으로 실패가 나왔다. → `python tests/check_output.py --input input.csv --output output.csv`로 바꾸고, `--expect-ok`(실패 0건까지 확인)는 모든 행이 권역 안일 때만 붙이도록 설명. 검사기도 predict.py와 같은 함수로 입력을 읽는다.
