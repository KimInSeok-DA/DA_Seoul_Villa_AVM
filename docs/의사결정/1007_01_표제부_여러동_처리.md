# 1007_01 건축물대장 표제부: 한 지번에 건물이 여러 동일 때

- 상태: 확정 (사용자 결정, 2026-10-07)

## 배경

표제부는 지번(PNU) 단위로 조회하는데, 한 지번에 주건축물이 여러 동인 경우가 있다. 실거래에는 동 정보가 없어서 거래가 어느 동인지 알 수 없다.

확인한 데이터 (매매 지번 9,928개 중):

| 항목 | 결과 |
|---|---|
| 주건축물이 여러 동인 지번 | 552개(5.6%), 이 지번의 매매 4,241건(전체의 11.5%) |
| 동끼리 사용승인 연도가 같음 | 91% |
| 동끼리 승강기 유무가 같음 | 97% |
| 동끼리 지상 층수가 같음 / 1층 이내 차이 | 77% / 89% |
| 상가 등 비주거 동이 섞임 | 11% |
| 실거래 건물명에 동 표기("B동" 등)가 있음 | 14% |

## 검토한 안

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 지번 단위로 합침 | 모든 거래에 같은 규칙. 간단하고 설명하기 쉬움. **예측 입력(지번·층·호, 동 없음)에도 그대로 적용** | 동마다 다른 경우(층수 23%, 연도 9%)는 정보가 뭉개짐. 상가 동이 섞이면 값이 왜곡됨 |
| B | 실거래 건물명·건축년도로 동을 추정해 매칭, 실패하면 A | 맞으면 가장 정확 | 건물명에 동 표기가 있는 경우가 14%뿐. **예측 입력에는 동이 없어 학습과 예측의 처리가 달라짐**. 매칭 규칙 검증에 시간이 듦 |
| C | 여러 동 지번은 표제부 변수를 비움 | 틀린 값을 넣을 위험이 없음 | 거래의 11.5%에서 승강기·층수·세대수를 버림(동끼리 91~97% 같은데도). 결측 처리 규칙이 따로 필요 |

## 결정

**A안. 지번 단위로 합치되, 다세대·연립(공동주택) 동만 쓴다.**

근거:
1. 과제 입력에 동이 없으므로 예측할 때도 지번 단위로만 건물 정보를 붙일 수 있다. 학습도 같은 방식이어야 한다(B는 학습에만 쓸 수 있는 정보에 기댐)
2. 동끼리 연도 91%, 승강기 97%가 같아 합쳐도 잃는 정보가 작다
3. 같은 건물 안의 층·호 차이는 호 단위 공시가격(`ho_key`)이 맡는다. 표제부는 건물 수준 정보(연식·승강기·규모)만 맡는다
4. 이 모델은 다세대(빌라) 시세 모델이라 상가 동 정보는 필요 없다(사용자 판단). 수집한 실거래는 모두 연립다세대 거래라 상가 거래는 처음부터 없다

## 처리 규칙

- 대상: 주건축물 중 공동주택(다세대·연립) 동. 지번에 그런 동이 없으면(1층 상가 + 위층 다세대처럼 주용도가 근린생활시설로 등록된 건물 등) 주건축물 전체를 쓴다
- 승강기: 어느 동이든 있으면 있음 / 지상·지하 층수: 최대 / 세대수: 합계 / 동 수: 개수
- 사용승인일·구조: 세대수가 가장 많은 동(대표 동) 기준. 실거래에는 건축년도가 따로 있으므로 학습 데이터의 연식은 실거래 값을 우선한다
