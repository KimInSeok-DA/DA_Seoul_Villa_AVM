## 구간·신뢰도 보정 (브랜치 `model/calibration`)
- 보정 표본: 최종 검증 건물 632개는 거래까지 빼고, 나머지 후보 2,527개를 5개 폴드로 나눠 검증 건물처럼 추정(A·B × 면적 있음·비움 10,108건). 최종 검증과 분리해 누수 방지
- 오차를 설명하는 변수 확인: 하나씩은 약함(순위상관 0.1 안팎) — 동네 비율의 흩어짐, 소형 면적, 강남, 같은 건물 비율이 동네와 다른 정도, 같은 건물 거래 수. 합친 오차 점수(최소제곱)는 교차 적합 순위상관 0.20, 점수 10분위 중앙값 오차 9.1% → 18.5%
- 구간 = 점수 10분위별 log 오차 10·90% 분위수, 신뢰도 = 점수 10분위별 ±20% 적중률(단조 보정) → `data/processed/calibration.json`(`src/build_calibration.py`), predict.py 반영
- 최종 검증 건물(보정에 안 씀): 80% 구간 포함률 A 65.0 → 81.8%, B 60.4 → 83.2%(면적 비움도 80% 이상), 신뢰도-오차 순위상관 B −0.13 → −0.27, 신뢰도 값 3개 → 10개. 신뢰도 0.78 구간 실제 ±20% 적중 81.5%, 0.54 구간 48.9%. 구간 폭은 넓어짐(상한/하한 1.33 → 1.55) → [1007_09](../의사결정/1007_09_구간_신뢰도_보정.md), `notebooks/02_구간_신뢰도_보정.ipynb`
- 추정값·오차율 불변(보정 전 지표가 1007_08과 같음을 재확인). 표본 20건·예외 10건 규격 통과, 보정표 재생성 해시 동일
- 재점검(사용자 요청): 면적 비움 입력의 신뢰도도 실제와 맞음(평균 0.65·0.70 vs 실제 ±20% 적중 66.5%·69.9%), 홀드아웃 분할 그대로(632개 동일), 노트북 01 재실행 지표·시점 지수 동일(예측표는 열만 추가)
- 정정: ㎡단가 추정(공시가격 없음)의 신뢰도 상한 0.30이 근거 없이 높았음 — 보정 표본 ±20% 적중 2/20건, 최종 검증 0/4건 → 0.10으로 고정. 1007_08 상태를 1007_09로 연결

## ML 비교와 최종 모델 선정 (브랜치 `model/ml-compare`)
- 1차 실험: B1 / XGBoost 직접 / B1 + XGBoost 잔차를 같은 최종 검증(632개, 상황 A·B)에서 비교. Pipeline + GridSearchCV(건물 단위 GroupKFold), 학습 행의 B1 근거는 예측 때처럼 앞선 거래·자기 건물 뺀 폴드로 만듦. 세 모델 모두 B1보다 중앙값 오차 1.4~2.0%p 낮음
- 사용자 질문(XGBoost만 썼는지, 다른 모델은, 새 데이터·물가를 고려하면 무엇으로 판단하는지)으로 비교 확대: Ridge·KNN·RF·XGB × 직접/잔차/평균 13개 후보, 상황 T(2025-08까지 거래로 만든 모델로 그 뒤 1년을 맞힘) 추가, 선정 기준을 결과 전에 1007_10에 고정
- 시점 지수 수정: 학습 거래가 기준 달보다 일찍 끝나면 마지막 달 원값이 이어 붙던 문제 → 이동평균 값을 이어 붙임. 평소 실행 지수는 이전과 같음을 확인
- B1 통계 계산 벡터화(21초 → 0.6초, 통계·predict 출력 동일). predict.py 22초 → 7초
- 본 실험 5,071초. 결과: XGB-평균이 평균 순위 1.8·가장 나쁜 순위 2.3으로 1위, ±20% 적중 A 75.5%·B 78.6%·T 74.8%(B1 71.2·73.7·72.5%), 세 상황 모두 B1 대비 유의. RF-평균과는 대부분 우연 범위 안. 한쪽 방식만 쓰면 직접은 B·T, 잔차는 A에서 유의하게 밀림
- 상황 T: 모든 모델이 3~5% 낮게 추정(학습 뒤 오른 가격). 직접 방식이 더 낮음(−4.1% vs 잔차 −3.3%) → 실행할 때마다 다시 맞추는 구조 유지
- 사용자 결정: XGB-평균 채택 → [1007_10](../의사결정/1007_10_ML_비교.md), `notebooks/03_ML_비교.ipynb`(저장된 CSV만 읽음), `milestones/ml_compare/2026-10-07_ab3d32c/`
